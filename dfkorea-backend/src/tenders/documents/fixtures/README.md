# Tender extractor fixtures

These are synthetic, redistribution-safe documents generated by `node src/tenders/documents/fixtures/generate.cjs` from the backend directory. No downloaded tender documents, customer information, or parser-produced expected values are included. The generator writes test fixtures only; production extraction stays in memory.

All five `sample.*` files contain three paragraphs, in this order:

1. 소비전력 50W 이하
2. 광효율 130 lm/W 이상
3. 고효율 인증 필수

They then contain a two-column table with rows `항목 / 기준`, `소비전력 / 50W 이하`, `광효율 / 130 lm/W 이상`. The XLSX puts those paragraphs in rows 1–3 and the table in rows 5–7. Expected blocks and locations are handwritten in the spec.

- HWP: genuine CFB with a 256-byte HWP 5.0 FileHeader, raw-deflated DocInfo and BodyText/Section0, paragraph/table/list records. `inline.hwp` adds the actual extended table-control marker between two text fragments to verify before/table/after ordering. The encrypted/distribution/old-version variants set the corresponding header flags/version.
- HWPX: ZIP with OWPML section XML, OPF package/spine, and container metadata.
- DOCX: OOXML package with content types, root relationship, Word paragraphs and table.
- XLSX: ExcelJS writes a genuine workbook; `formatted.xlsx` adds cached formulas, numeric/percentage/date formats and a hidden sheet.
- PDF: valid cross-reference offsets, Type0/CID font descriptor and explicit ToUnicode CMap for Korean, positioned text and a drawn table. No font file is embedded. Image-only and mixed-page fixtures contain a 1×1 image XObject. The encrypted fixture uses real PDF Standard revision-2 encryption, including compressed/encrypted streams; the known test password `fixture-user` decrypts its Korean facts.
- Corrupt fixtures have invalid containers; tests also mutate valid internal structure in memory.
- Limit fixtures exercise stored XML over 10 MiB, 4,097 extra ZIP entries, high compression ratio, and forged uncompressed sizes. The large stored fixture compresses well in Git and exists solely to exercise pre-decode rejection.

PDF table detection is a conservative baseline/alignment heuristic, not layout reconstruction or OCR. Public production tender samples remain a deployment qualification step; these tests do not claim live document coverage.

Review regressions are generated separately with `node src/tenders/documents/fixtures/generate-review.cjs`: real DOCX footnote/endnote parts and references, a PNG nested below a hyperlink/run, and tabs in a paragraph and table cell. CFB metadata-only mutations, a regular-stream fixture and a hand-built version-4 sector layout are constructed in `cfb-guard.spec.ts`; unsafe metadata probes are stopped before any eager library call and before stream allocations.
