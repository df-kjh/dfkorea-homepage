# LH 입찰공고 직접 수집 설계

## 목표

LH 전자조달의 공개 입찰공고 중 LED 조명 제조사가 검토할 물품과 지급자재 공고를 수집하고, 기존 입찰 목록·필터·알림·문서 분석 흐름에 `LH` 출처로 연결한다.

## 수집 범위

- 공개 목록 주소 `https://ebid.lh.or.kr/ebid.et.tp.cmd.BidMasterListCmd.dev`를 사용한다.
- 업무구분 `30`(물품), `40`(지급자재)만 수집한다.
- LH 목록이 공고 등록일 대신 입찰 마감일을 검색하므로, 실행 시각 기준 최근 7일부터 앞으로 180일까지의 마감 공고를 조회한다.
- 목록의 제목을 LED 조명 후보 사전으로 먼저 좁힌 뒤 상세를 조회하고, 저장 여부는 기존 `TenderClassifier`가 최종 결정한다.
- 모든 페이지를 순차 처리하고 중복 공고는 `공고번호 + 공고차수`로 제거한다.

## 데이터 흐름

`LhTenderAdapter`가 목록과 상세 HTML을 받아 `NormalizedTender`로 변환한다. 상세에서 공고일, 금액, 계약 방식, 입찰 개시·마감·개찰 시각과 첨부 식별자를 수집하며 원본 필드는 `rawData`에 보존한다. `LhEnrichmentAdapter`는 저장된 `rawData`만 사용해 기초금액 근거와 안전한 첨부 참조를 발급한다. 분석 작업에서 LH 상세를 다시 요청하지 않는다.

LH 상세는 업무구분별 GET 주소를 사용한다. 사용자가 여는 `sourceUrl`에도 공고번호·차수·업무구분을 넣어 직접 상세를 연다.

## 첨부와 문서 분석

LH 첨부 다운로드는 `https://ebid.lh.or.kr/ebid.framework.download.dev`에 폼 POST가 필요하다. 첨부 참조는 `LH_PAGE` 출처와 공고 identity, 공개 상세에서 검증한 표시 파일명·저장 파일명을 담는다. 공용 문서 fetcher는 발급된 참조, 호스트, 경로, 쿼리 키, identity가 모두 일치할 때만 POST한다.

HWP, HWPX, PDF, DOCX, XLSX는 기존 추출기를 사용한다. 일반 ZIP은 기존 압축 폭탄 제한으로 한 번만 안전하게 풀고, 최상위의 지원 문서만 분석한다. 중첩 ZIP, 암호화 파일, 경로 이탈, 전체 확장 용량 초과는 실패 또는 미지원으로 남긴다.

## 장애 처리

- 기본 요청 간격은 1,500ms이며 요청은 순차 실행한다.
- 네트워크·HTTP 오류는 해당 작업 실패로 기록하고 다른 출처 수집은 계속한다.
- 목록 헤더나 상세 필수 필드가 사라지면 `STRUCTURE_CHANGED`로 실패해 잘못된 데이터를 저장하지 않는다.
- 페이지 상한과 후보 상세 상한을 넘으면 `PARTIAL`로 끝내고 실패 내역을 남긴다.
- 응답 HTML과 첨부파일에는 크기 제한을 둔다.
- 로그인 화면, 보안문자, 비정상 리다이렉트는 정상 빈 결과로 취급하지 않는다.

## 애플리케이션 연결

- `TenderSource.LH`와 프런트엔드 `TenderSource` 타입, 출처 필터·표시명을 추가한다.
- LH 물품·지급자재는 목록, 달력, 메일, 분석 큐에 포함한다.
- LH 낙찰 corpus가 없으므로 낙찰 통계 가격은 제공하지 않는다. 구조화된 기초금액과 문서 요구조건은 표시한다.
- `LH_TENDER_ENABLED`, `LH_TENDER_BASE_URL`, `LH_TENDER_REQUEST_INTERVAL_MS`를 환경설정으로 제공한다. 기본값은 비활성화이며 운영자가 직접 수집을 명시적으로 켠다.

## 검증

- 실사이트 구조를 축약한 목록·상세 fixture로 정상, 페이지 이동, 중복, 구조 변경, 제한 초과를 테스트한다.
- 첨부 참조 위조, 다른 호스트·경로, 잘못된 identity, GET 우회가 차단되는지 테스트한다.
- ZIP 내부 지원 문서 추출과 중첩·폭탄·경로 이탈 거부를 테스트한다.
- LH가 분석 큐, 목록, 메일에서 보이고 관리자 필터·레이블이 정상인지 테스트한다.
- 백엔드 전체 CI와 프런트엔드 테스트·타입 검사·빌드를 통과시킨다.

## 문서

`docs/menus/tenders.md`, `DEPLOYMENT.md`, `dfkorea-backend/.env.example`을 갱신한다. DB 스키마는 문자열 `source` 컬럼을 그대로 사용하므로 변경하지 않는다.
