# 주차장 3D Hero 설계

## 목표

홈페이지 Hero의 MP4 배경을 실시간 3D 주차장 장면으로 교체한다. 카메라는 신축 주차장의 중앙 통로와 하행 램프를 약 25초 동안 천천히 지나가며, 천장의 단순화된 몰드바 조명과 벽면의 단순화된 벽부등을 보여준다. 각 제품 조명은 평상시 50% 밝기를 유지하고, 사용자가 해당 제품을 가리키거나 누르는 동안에만 100%로 밝아진다.

현재 Hero의 제목, 부제, 제품 보기 CTA, 스크롤 이동, 스크롤 패럴랙스와 페이드 동작은 유지한다. 실제 제품 3D 에셋은 사용하지 않고 제품 특징을 연상시키는 절차적 저폴리곤 모델을 사용한다.

## 범위

### 포함

- Three.js로 생성하는 브라우저 전용 실시간 3D 배경
- 신축 주차장을 표현하는 저폴리곤 구조물과 최소한의 표지 요소
- 단순화된 몰드바 및 벽부등 모델
- 약 25초의 자동 카메라 이동과 반복 전환
- 개별 조명의 포인터 hover 및 터치 press 상호작용
- 데스크톱과 모바일의 렌더링 품질 차등 적용
- WebGL 미지원, 컨텍스트 손실, 초기 성능 기준 미달 환경의 정적 이미지 폴백
- `prefers-reduced-motion` 사용자의 정지 카메라 모드
- 홈페이지 메뉴 기능 현황 문서 추가

### 제외

- 실제 제품과 치수가 일치하는 정밀 3D 모델
- 사용자의 자유로운 카메라 이동, 회전 또는 장면 탐색
- 차량, 사람, 복잡한 주차장 설비의 사실적 시뮬레이션
- 관리자 화면에서 장면이나 동선을 편집하는 기능
- 외부 3D 모델 파일 다운로드 또는 런타임 CMS 연동

## 기술 접근법

Three.js를 직접 사용한다. Vue 전용 추상화 프레임워크를 추가하지 않아 장면 수명주기, 카메라 경로, raycasting, 리소스 해제를 명시적으로 제어한다. 미리 렌더링한 영상은 개별 조명의 실제 화면 위치와 상호작용 영역을 일치시키기 어렵기 때문에 사용하지 않는다.

Three.js 초기화는 Vue 컴포넌트가 브라우저에 마운트된 후에만 수행한다. Nuxt SSR에서는 Canvas나 WebGL API에 접근하지 않는다.

## 컴포넌트와 모듈

### `HeroSection.vue`

기존 텍스트, CTA 이벤트, 스크롤 이동, 콘텐츠 패럴랙스와 페이드의 소유권을 유지한다. 동영상과 동영상 로딩 스피너를 제거하고 `ParkingGarageScene`을 배경 레이어에 배치한다. 장면 위에 기존과 유사한 어두운 오버레이와 하단 그라데이션을 적용해 텍스트 대비를 유지한다.

기존 `public/videos/HeroSection.mp4` 파일은 이번 변경에서 삭제하지 않는다. Hero에서는 더 이상 요청하지 않으므로 런타임 전송 비용은 발생하지 않으며, 필요할 경우 쉽게 복구할 수 있다.

### `ParkingGarageScene.vue`

Canvas 컨테이너와 정적 폴백 이미지, 준비 상태 전환을 관리한다. 장면 생성 실패, WebGL 미지원, 컨텍스트 손실 또는 초기 성능 기준 미달 시 폴백을 유지한다. 장면이 준비되면 폴백 이미지 위로 Canvas를 짧게 페이드 인한다.

컴포넌트가 해제될 때 scene controller의 `dispose`를 호출한다. Canvas는 카메라 조작을 제공하지 않으며 CTA 클릭과 페이지 스크롤을 방해하지 않는다.

### `parkingGarageScene.ts`

renderer, scene, camera, animation frame, resize, visibility, pointer 이벤트의 수명주기를 소유하는 controller를 제공한다. 외부에는 생성, 시작, 일시 중지, 해제와 제한된 상태 콜백만 노출한다.

탭이 숨겨지면 animation frame을 중단하고, 다시 보이면 마지막 프레임 이후의 큰 시간 차이를 누적하지 않고 현재 루프 시간부터 재개한다. WebGL context가 손실되면 렌더링을 중지하고 Vue 컴포넌트에 폴백 전환을 알린다.

### `parkingGarageModels.ts`

주차장 바닥, 천장, 벽, 기둥, 차선, 주차 구획, 방향 표지와 제품 모델을 절차적으로 생성한다. 복잡한 차량과 소품은 만들지 않는다.

몰드바와 벽부등 생성 함수는 보이는 mesh, 발광 material, 실제 광원을 하나의 fixture 단위로 묶어 반환한다. 각 fixture는 독립적인 상호작용 ID와 hit target을 가진다. 재질과 geometry는 가능한 범위에서 공유하고, fixture 단위 상태만 분리해 메모리 사용과 draw call을 제한한다.

### `parkingGaragePath.ts`

0~25초의 정규화된 루프 진행도를 카메라 위치와 주시점으로 변환한다. 경로는 다음 구간을 순서대로 지난다.

1. 중앙 통로에서 사람 눈높이로 천천히 전진
2. 천장 몰드바 아래를 통과
3. 완만한 회전으로 하행 램프 진입
4. 벽부등이 있는 벽면 가까이를 통과
5. 기둥과 벽이 시야를 가리는 짧은 구간에서 시작 위치로 전환

카메라에는 작은 상하 움직임만 더하고 빠른 회전, 강한 흔들림, 역재생은 사용하지 않는다. 반복 경계의 위치 전환은 차폐 구간 안에서만 일어나도록 경로와 구조물을 함께 조정한다.

### `parkingGarageQuality.ts`

실행 환경을 `desktop`, `mobile`, `fallback`으로 분류하는 순수 로직을 제공한다.

- 데스크톱은 그림자, 전체 fixture 수, 최대 device pixel ratio 1.5를 사용한다.
- 모바일은 그림자 해상도와 fixture 수를 낮추고 device pixel ratio를 1.0으로 제한한다.
- WebGL을 만들 수 없거나 초기 프레임 성능이 기준을 지속적으로 충족하지 못하면 `fallback`으로 전환한다.
- `prefers-reduced-motion`은 품질 분류와 별개로 카메라 진행만 정지하며 조명 상호작용과 렌더링은 유지한다.

성능 판정은 첫 화면의 일시적인 컴파일 비용에 과민하게 반응하지 않도록 짧은 준비 구간 이후 연속된 프레임 표본으로 결정한다. 한 번 폴백으로 전환한 세션에서는 자동으로 3D를 재시작하지 않는다.

## 장면 디자인

색상은 밝은 회색 콘크리트, 흰색 차선, 제한적인 방향 표지 색상을 사용해 신축 주차장 분위기를 만든다. 환경광은 조명이 꺼져도 공간의 윤곽이 보일 정도로만 제공한다. 제품의 발광부는 따뜻하지 않은 중성 백색 계열로 통일한다.

천장 몰드바는 중앙 통로의 진행 방향을 따라 반복 배치한다. 벽부등은 하행 램프의 한쪽 벽면에 일정한 간격으로 배치해 카메라가 제품 가까이를 지나가게 한다. 제품 모델은 브랜드의 용도와 실루엣을 전달할 정도로 단순화하며 실제 제품의 정확한 형상이나 치수를 암시하지 않는다.

Hero 텍스트 뒤에는 전체 어두운 오버레이와 하단 흰색 전환 그라데이션을 둔다. 오버레이는 3D Canvas와 별도 DOM 레이어이므로 장면의 pointer 좌표 계산과 분리하되, 조명 hit test를 위한 포인터 좌표는 Hero 영역에서 수집한다.

## 조명 상호작용

각 fixture는 기본 강도 `0.5`, 활성 강도 `1.0`을 갖는다. raycaster가 fixture의 hit target과 교차하면 해당 fixture만 목표 강도 1.0으로 바뀌며, 나머지 fixture는 0.5를 유지한다. 포인터가 벗어나거나 Canvas 영역을 떠나면 해당 fixture의 목표 강도를 0.5로 되돌린다.

보이는 발광 재질과 실제 광원의 강도를 약 180ms 동안 보간해 갑작스러운 점멸을 피한다. 한 프레임에서 가장 가까운 fixture 하나만 활성 대상으로 선택한다.

터치 환경에서는 fixture 위에서 pointer down 상태인 동안 같은 효과를 적용하고 pointer up, pointer cancel 또는 스크롤 시작 시 즉시 해제한다. 장면은 drag나 pinch를 소비하지 않으며 페이지의 세로 스크롤을 막지 않는다.

## 로딩, 실패와 폴백

Hero는 처음부터 `public/images/home/parking-garage-fallback.webp`를 표시한다. 3D 초기화와 첫 프레임이 성공하면 Canvas opacity를 올려 짧게 전환한다. 기존의 전체 검은 화면과 동영상 로딩 스피너는 제거한다.

다음 상황에서는 폴백 이미지를 계속 표시한다.

- WebGL renderer 생성 실패
- 장면 구성 또는 첫 렌더 오류
- WebGL context 손실
- 초기 성능 표본이 정한 기준을 지속적으로 밑돎

장면 실패는 홈페이지의 나머지 콘텐츠나 CTA 동작을 막지 않는다. 사용자에게 기술 오류 메시지는 노출하지 않고 개발 환경 콘솔에는 제한된 진단 정보를 남긴다.

폴백 이미지는 구현된 장면의 대표 시점에서 생성해 3D와 시각적 차이를 줄인다. 이미지 생성이 불가능한 환경에서도 Hero가 깨지지 않도록 기존 `main-hero.jpg`를 최종 CSS fallback으로 유지한다.

## 접근성과 반응형 동작

- `prefers-reduced-motion: reduce`에서는 카메라를 대표 시점에 고정한다.
- 고정 상태에서도 hover와 press에 따른 개별 조명 밝기 변화는 유지한다.
- 장면은 장식적 배경이므로 접근성 트리에서 숨기고, Hero의 제목과 CTA DOM 구조는 그대로 유지한다.
- Canvas 상호작용은 키보드 포커스를 요구하지 않는다. 조명 밝기 효과는 정보를 전달하거나 기능 수행에 필수적이지 않은 장식 효과다.
- resize 시 renderer와 camera aspect를 갱신하되 pixel ratio 상한은 현재 품질 설정을 따른다.

## 테스트 전략

### 자동 테스트

- 카메라 경로가 0~25초 범위에서 반복되고 주요 구간을 올바른 순서로 통과하는지 검증한다.
- 데스크톱, 모바일, reduced-motion, WebGL 미지원 입력이 올바른 품질 및 모션 설정을 만드는지 검증한다.
- fixture의 기본 강도가 0.5이고 활성 목표 강도가 1.0이며 해제 후 0.5로 복귀하는지 검증한다.
- controller 해제 시 animation frame, DOM 이벤트, renderer와 생성한 Three.js 리소스가 정리되는지 검증한다.
- Hero CTA 이벤트와 스크롤 함수가 3D 교체 후에도 유지되는지 컴포넌트 테스트로 검증한다.

Three.js 렌더 결과 전체를 픽셀 스냅샷으로 고정하지 않는다. 브라우저와 GPU에 따라 달라질 수 있는 출력 대신 카메라, 품질, 조명 상태와 수명주기 경계를 테스트한다.

### 수동 검증

- 데스크톱과 모바일 viewport에서 장면이 Hero 전체를 채우는지 확인한다.
- 제목과 CTA의 대비, 클릭, 스크롤 이동을 확인한다.
- 반복 전환이 기둥 또는 벽 뒤에서 가려지는지 확인한다.
- 움직이는 장면에서 개별 fixture hit test가 시각적 위치와 일치하는지 확인한다.
- 모바일 press와 페이지 스크롤이 충돌하지 않는지 확인한다.
- reduced-motion, WebGL 미지원과 context loss 폴백을 확인한다.

완료 전 관련 Vitest, `npm run type-check`, `npm run build`를 실행한다. 변경 파일 범위에 ESLint를 적용하며 자동 수정이 관련 없는 사용자 코드를 바꾸지 않도록 결과를 검토한다.

## 문서 갱신

`docs/menus/home.md`를 새로 만들고 다음 구성을 유지한다.

- `구현 완료`: 실시간 3D Hero, 자동 카메라 루프, 개별 조명 상호작용, 반응형 품질과 폴백
- `미구현`: 정밀 제품 모델, 관리자 편집 기능, 자유 카메라 조작
- `부족하거나 개선이 필요한 기능`: 단순화된 모델의 한계, 기기별 GPU 성능 차이, 실제 모바일 기기 검증 필요성
- `관련 파일`: Hero와 3D 관련 컴포넌트, 유틸리티, 폴백 에셋
- `갱신 규칙`: 홈페이지 Hero 장면, CTA, 상호작용 또는 폴백 변경 시 함께 갱신

## 완료 기준

- MP4가 Hero에서 더 이상 요청되지 않고 3D 장면이 배경으로 표시된다.
- 카메라가 중앙 통로와 하행 램프를 약 25초 동안 지나고 차폐 구간에서 반복된다.
- 몰드바와 벽부등은 기본 50%, 개별 hover 또는 press 동안 100% 밝기로 부드럽게 전환된다.
- 기존 Hero 텍스트, CTA, 스크롤 동작과 콘텐츠 패럴랙스가 유지된다.
- 모바일 저품질 모드, reduced-motion 정지 모드와 정적 폴백이 동작한다.
- 컴포넌트 해제 후 렌더링과 이벤트가 남지 않는다.
- 홈페이지 기능 현황 문서가 구현 상태와 한계를 정확히 기록한다.
- 자동 테스트, 타입 검사와 프로덕션 빌드가 통과한다.
