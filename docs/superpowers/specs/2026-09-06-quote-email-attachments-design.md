# 온라인 견적 사진의 메일 첨부 전용 처리

사용자 요청: R2에 사진을 저장하지 않고 실제 메일 첨부로 수신하도록 변경한다. 구현 요청은 승인되어 있으며 운영 배포·실제 외부 발송은 포함하지 않는다.

## 설계

- R2/로컬 파일 저장 대신 기존 PostgreSQL에 압축된 메일 첨부 bytes를 잠시 보관한다. 메일 큐와 재시도 안정성을 유지하며 별도 버킷/키 설정을 제거한다.
- UI/API의 사진 3장, 원본5MiB/40MP, 정지 JPEG/PNG/WebP, 변환후2MiB/전체6MiB 제한은 유지한다. 기존 upload clientAttachmentId와 접수 idempotency도 유지한다.
- 사진 bytes는 별도 payload 테이블에 bytea로 보관하여 목록/상세의 SELECT * 결과에 포함되지 않게 한다. 준비중 사진24시간, 제출후 min(회사 보유기간,7일)까지 보관한다.
- NAVER WORKS202 수락 상태 저장과 bytes 삭제는 한 DB트랜잭션에서 실행한다. 수락 후 사진은 메일 첨부에서 확인하며 서버에서 재다운로드하지 않는다. 메타데이터와 견적 내용은 기존 보유기간을 따른다.
- 명백한 일시발송실패에는 bytes를 유지해 재시도한다. 불명확한 결과는 기존대로 자동 재발송하지 않는다. 7일만료시 bytes 삭제, 메타데이터 유지로 사진을 빠뜨린 메일이 나가지 않도록 한다. payload 없는 요청은 발송/수동재전송 거절 및 명확한 상태를 남긴다.
- cleanup은 발송중인 bytes를 중간 삭제하지 않는다. 삭제 후 사용불가와 타세션/제출된 사진 보호를 유지한다. 재시도·서버중단에도 보유기간이 계속 연장되지 않는다.
- 기존 CreateQuoteTables migration은 변경하지 않고 새 forward migration을 추가한다. 이전 R2 사진은 자동 이관하지 않으며 이를 사진없이 발송하지 않는다. 아직 미배포 기능이지만 기존자료가 있다면 전환 전 별도처리가 필요함을 문서화한다.
- 개인정보 안내에는 견적정보 보유기간과 사진 임시보관기간을 구분한다. 동의 버전을 변경하여 이전 안내에 대한 동의가 새로운 정책을 대신하지 않게 한다.
- 운영 환경에서 R2·로컬파일설정 없이 접수와 메일첨부가 동작해야 한다. 국세청/NAVER WORKS/DB 연결은 계속 필요하며 worker는 운영 환경에서 기본 실행한다. 견적 전용 환경변수 없이 기존 JWT 키·CORS/사이트 주소와 기본365일 보유기간을 사용한다. 선택 재정의는 docs/quote-setup.md를 따른다. DB 백업의 물리삭제 시점과 수신메일 보유는 이 애플리케이션의 즉시삭제 범위에 포함되지 않는다.
