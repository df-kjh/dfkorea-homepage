# 온라인 견적 기능 현황

## 구현 완료

- 견적 전용 환경변수 없이 기존 JWT 키·CORS/사이트 주소를 재사용한다. 견적정보 기본 보유기간은 365일이며 운영 환경에서 메일·정리 작업자가 자동 실행된다. 기본값 변경용 `QUOTE_*` 변수만 선택적으로 유지한다.

- 공개 페이지의 우하단 `온라인 견적`, 홈 상담 문의 선택, 제품 상세 `견적에 담기`에서 같은 견적 창을 연다. 관리자 화면에서는 표시하지 않는다.
- 기업 정보 → 제품 선택 → 요청 확인의 3단계와 접수 완료 화면을 제공한다. 데스크톱은 440px 비모달 창, 640px 미만은 배경 스크롤 및 포커스를 제한하는 하단 대화상자로 표시한다.
- 헤더·단계·하단 버튼을 고정하고 본문만 스크롤한다. ESC/최소화 뒤 입력과 현재 단계가 유지되며 시작 버튼으로 포커스를 복귀한다. 화면 키보드와 안전 영역, 동작 줄이기 설정을 반영한다.
- 회사명, 사업자등록번호, 대표자명, 개업일자, 담당자명, 이메일을 필수로 받고 전화번호는 선택 입력한다. 사업자 정보 변경·동의 철회 시 확인 상태를 해제하고, 늦게 도착한 이전 확인 결과를 폐기한다.
- 동의 전에 수집 목적, 필수·선택 항목, 거부 시 제한을 안내하고 요청 확인에서도 전문을 열어볼 수 있다. 견적 정보·첨부 기록의 보유기간은 서버 설정을 따르고 사진 파일은 별도로 접수 전 최대 24시간, 접수 후 `min(견적 정보 보유기간, 7일)`만 임시 보관한다고 안내한다. 메일 서비스 발송 수락 후 서버 사진을 삭제해도 수신 메일 첨부 사본과 백업 삭제 시점은 별도 정책을 따른다는 점을 명시한다.
- 별도의 익명 작성 세션으로 기업 등록정보 확인을 요청한다. 입력 형식 통과를 진위확인 성공으로 표시하지 않으며 불일치, 미등록, 휴폐업, 외부 확인 장애, 만료를 안내한다.
- 제품명·모델명 검색과 실제 카탈로그 기반 카테고리·소비전력·인증·색온도·옵션 필터를 제공한다. 300ms 지연 검색, 이전 응답 폐기, 조건 칩, 초기화, 결과 수, 더 보기, 로딩·실패·결과 없음을 구분한다.
- 희망 소비전력·색온도·옵션을 선택하거나 상담 후 결정으로 담는다. 필요한 인증은 제품의 등록 인증과 구분한다. 같은 제품·선택 사양은 수량을 합산하고 다른 사양은 별도 품목으로 유지한다.
- 자사 제품과 직접 입력 제품을 함께 담을 수 있다. 직접 입력은 제품명·수량·요구 사양 설명이 필수이고 나머지 세부 사양은 선택이다. 20품목, 정수 수량 1~999,999개 제한과 수량 수정·삭제를 제공한다.
- 요청 전체 최대 3장, 장당 5MB의 JPEG·PNG·WebP 사진을 직접 입력 품목에 연결한다. 미리보기, 개별 삭제·교체를 제공하고 한도를 넘으면 기존 사진을 보존한다. 원격 삭제·교체 중에는 단계 이동과 제출을 잠그고 서버 삭제 성공 전까지 원본과 미리보기를 유지한다.
- 제출 시 사진을 비공개 PostgreSQL 임시 영역에 업로드한 후 접수를 요청한다. R2 버킷이나 로컬 파일 저장 설정은 필요하지 않다. 사진 선택마다 고유 식별자를 유지해 업로드 응답이 유실되어도 같은 파일을 중복 저장하지 않으며, 교체 사진에는 새 식별자를 사용한다. 성공한 업로드는 재사용하고 실패한 사진부터 재시도한다. 작성 중이지만 목록에 담지 않은 품목의 사진은 제출하지 않는다.
- 결과가 불명확한 통신 실패는 원래 요청과 중복 방지 키를 보관해 같은 요청으로 결과를 다시 확인한다. 명확한 입력 거절은 수정할 수 있도록 잠금만 해제한다. 만료된 익명 세션에서 불명확한 접수를 새로운 요청으로 자동 재발송하지 않는다.
- 저장된 접수번호를 성공 기준으로 표시하며 성공 후 새 견적 작성을 시작할 수 있다. 메일 서비스가 발송을 수락하면 수락 상태와 서버 사진 파일 삭제를 한 트랜잭션으로 반영한다. 메일 최종 배달을 고객 접수 성공과 동일시하지 않는다.
- 브라우저의 작성 중 상태(개인정보, 원본 사진, 작성 세션 토큰)는 클라이언트 메모리에만 유지하며 브라우저 영구 저장소 및 SSR 응답 데이터에 넣지 않는다. 관리자 인증 토큰·401 로그인 이동 처리는 견적 통신에 사용하지 않는다.

## 미구현

- 자동 단가 산정, 확정 견적서 자동 발급, 실시간 상담원 채팅, 고객 접수 확인 메일, 새로고침 후 작성 복원은 제공하지 않는다.
- 실제 국세청 운영 키와 승인된 사업자 정보로 상호 비교를 검증하고, NAVER WORKS 실제 수신·사진 열기를 확인하는 운영 연결 검증은 아직 수행하지 않았다.
- 공개 화면에 접수번호로 개인정보를 조회하는 기능은 제공하지 않는다.

## 부족하거나 개선이 필요한 기능

- 현재 구현은 실제 접수 API 연결 코드이며 mock 확인 성공으로 우회하지 않는다. 국세청 상호 검증 계약 확인·운영 키, NAVER WORKS 인증, PostgreSQL 마이그레이션, 운영 작업자의 실행과 회사 보유정책 일치를 확인하기 전에는 실제 서비스 운영 완료로 볼 수 없다.
- 표시된 전력·인증·옵션 조합의 실제 공급 가능 여부는 담당자의 검토가 필요하다. 담당자의 재직·대표권·이메일 소유권 인증은 이번 사업자 등록정보 확인에 포함되지 않는다.
- 브라우저에서는 형식·크기를 먼저 검사하고 서버에서 실제 디코딩, 픽셀 한도, 메타데이터 제거, 축소·압축 및 소유권을 검증한다. 모든 기기와 가상 키보드 조합의 실기기 검증은 추가할 수 있다.
- 결과 미확인 상태로 작성 세션이 만료된 경우 입력을 유지하고 기존 전화·이메일로 접수 여부를 문의하도록 안내한다. 세션 간 자동 접수 이관은 제공하지 않는다.
- 사진이 삭제되거나 임시 보관기간이 만료되면 사진 없이 메일을 보내거나 수동 재전송하지 않는다. 발송 수락 후 사진은 수신 메일의 첨부에서 확인해야 하며 서버 재다운로드는 제공하지 않는다. 이전 R2 저장 사진을 임시 DB 영역으로 자동 이관하지 않으므로 기존 미발송 자료가 있다면 전환 전에 별도로 처리해야 한다.
- 브라우저에 남아 있는 원본 사진과 개인정보는 새로고침하면 사라진다. 온라인 접수 불가 시 입력을 보관한 채 전화·이메일 문의와 재시도를 제공한다.

## 갱신 규칙

- 진입점·기업 정보·검증·동의·사양 검색·담은 품목·사진·접수·메일 처리 방식이 바뀌면 이 문서를 같은 작업에서 갱신한다.
- 홈 또는 제품 페이지 진입점·검색 조건이 바뀌면 해당 메뉴 문서도 함께 갱신한다.
- 국세청 상호 비교, 실제 메일 첨부 수신, 사진 임시 보관·발송 수락 후 삭제, 운영 보유기간은 검증 증거가 있을 때만 외부 연동 완료로 표시한다.
- DB 구조가 바뀌면 실제 마이그레이션과 `database-schema.md`를 함께 갱신한다.
