# 관리자 보안 점검·보완 범위

사용자 요청: 로그인부터 관리자 기능까지 보안 문제를 확인하고 보완을 적용한다. 운영 데이터 변경·침투 테스트는 하지 않고 코드 검토, 공개 GET/헤더 확인, 격리된 로컬 회귀 테스트로 검증한다.

## 확정된 개선 범위

1. 업로드·삭제를 관리자 인증 뒤에 실행하고, 허용 폴더·파일 형식·실제 바이트·크기를 검증한다. 삭제는 해당 서비스가 생성한 공개 업로드 객체로 제한한다.
2. 브라우저 localStorage의 관리자 bearer 토큰을 제거한다. Nuxt 같은 출처 `/api/admin/` 경유 요청과 HttpOnly/Secure/SameSite 쿠키를 사용한다. 서버는 고정된 upstream과 명시적 경로·메서드만 허용하고, 상태 변경 요청의 출처를 검증한다.
3. 로그인 실패를 일반화하고 입력 길이·반복 시도를 제한한다. JWT 기본 수명은 1시간이며 현재 관리자·비밀번호 상태와 대조한다. 로그아웃은 쿠키를 삭제한다.
4. 운영 CORS는 정확한 출처 허용 목록만 사용한다. 관리자 응답에 no-store/noindex, 프레임 삽입 방지·MIME 추론 방지 등 호환 가능한 헤더를 적용한다.
5. 확인된 제품명 HTML 삽입 경로를 제거하고, 공개 보안 권고에 해당하는 실행 의존성을 호환 가능한 패치로 갱신한다.

## 보존 및 한계

- 공개 제품·소식·인증 조회, 온라인 견적의 별도 토큰 흐름, 관리자 파일 업로드 및 첨부 다운로드를 유지한다.
- 비밀번호 변경·계정 생성·실제 메일 발송·운영 파일 삭제를 점검 수단으로 사용하지 않는다.
- MFA/외부 IdP, 영속 세션 테이블은 이번 범위에 추가하지 않는다. 이미 탈취된 bearer 토큰의 로그아웃 즉시 폐기는 지원하지 않으므로 만료까지 최대 1시간의 잔여 위험을 기록한다.
- 프로세스 메모리 기반 로그인 제한은 인스턴스별이며 재시작 때 초기화된다. 다중 인스턴스 환경에는 공유 저장소 또는 WAF 제한이 추가로 필요하다.
- 기존 관리자 세션은 인증 방식 변경으로 재로그인이 필요할 수 있다. 데이터 스키마 변경은 계획하지 않는다.
